# Rust 通信服务协议

## 通用消息规则（协议 v1）

- 仅在本机 TCP 通信，默认地址为 `127.0.0.1:7878`。每行一个 UTF-8 JSON 对象，接受 LF 或 CRLF；字符串内换行使用 JSON 转义。
- 一条完整消息的 UTF-8 编码最多 65,536 字节，不含行尾分隔符。发送方必须遵守此限制；超长请求尽量返回 `line_too_long` 后关闭连接。
- 同一连接内请求与响应一一对应、顺序处理。不要求同连接请求多路复用。
- `id` 为 0 到 9,007,199,254,740,991 的整数，不能是布尔值、小数或指数形式。`action` 为字符串。
- JSON 必须使用有效 Unicode 标量值和有限数字，不接受 NaN、Infinity 或无法表示为有限数的数字。对象键不应重复。
- 先检查 JSON，再检查对象、id 和 action 类型，再判断动作，最后检查该动作的字段和参数。
- 缺字段、额外字段或参数类型错误返回 `invalid_request`；不存在或当前阶段未实现的动作返回 `unknown_action`。
- 无法取得有效 id 时响应 id 为 null；否则错误响应保留请求 id。错误说明文字不要求逐字一致，代码和结构必须一致。
- 合法连接中的业务/JSON 错误响应后应可继续请求；EOF 正常关闭，只有半条消息的 EOF 直接关闭。超时、异常断开及退出取消不保证返回响应。
- 成功响应恰有 `id/ok/data`；错误响应恰有 `id/ok/error`，error 含 `code/message`。响应过大返回 `response_too_large`，保留连接。

```json
{"id":1,"action":"ping"}
{"id":1,"ok":true,"data":"pong"}
{"id":2,"action":"missing"}
{"id":2,"ok":false,"error":{"code":"unknown_action","message":"action is not supported"}}
```

错误代码：`invalid_json`（含非法 UTF-8）、`invalid_request`、`unknown_action`、`line_too_long`、`response_too_large`。

## 本项目动作

| action | 请求字段（除 id/action） | 成功 data | 完成阶段 |
|---|---|---|---|
| ping | 无 | `"pong"` | 基线已有 |
| echo | data：字符串 | 原字符串 | 协议扩展 |
| delay | milliseconds：0–10,000 的整数；data：字符串 | 等待后返回原字符串 | 协议扩展 |

milliseconds 不接受布尔值、小数或指数形式；额外字段按 invalid_request 处理。

```json
{"id":2,"action":"echo","data":"hello"}
{"id":2,"ok":true,"data":"hello"}
{"id":3,"action":"delay","milliseconds":1000,"data":"later"}
{"id":3,"ok":true,"data":"later"}
```

## 基线与最终连接行为

基线两种服务端每个连接只处理一条完整请求或错误消息，响应后关闭连接，再接受下一连接。候选人完成连续交互阶段后应支持同一连接多条请求，以及非法请求之后继续处理合法请求。

基线使用标准读行，未提供完整长度保护、读取超时、并发和退出管理；只在本机使用公开的小消息验证基线。后续阶段需要完善以下行为：

| 场景 | 起始代码当前行为 | 同步/异步服务端完善后的要求 |
|---|---|---|
| 一条完整消息 | 处理后关闭连接 | 保持连接，继续处理下一条请求 |
| JSON 内容完整但缺少行尾换行，随后 EOF | 仍尝试解析并响应 | 视为未完成的帧，直接关闭 |
| 非法 UTF-8 | 读行失败，关闭连接 | 返回 `invalid_json`；完整错误帧之后仍可处理下一条请求 |
| 超长消息 | 标准读行，尚无长度保护 | 按字节限制读入，尽量返回 `line_too_long` 后关闭 |
| 等待输入、跨连接任务和退出 | 基础读写与进程结束 | 按后续阶段实现读取期限、并发及任务回收 |

EOF 表示对方结束发送；JSON 文本完整也需要行尾换行才构成完整消息。两种服务端都需要验证前四项；异步服务端还需完成跨连接并发和退出管理。

## 超时与异步生命周期

这里的“有界退出”指服务端在限定时间内完成清理并结束，避免一直等待尚未完成的连接。

- 客户端发送完整请求后等待完整响应，默认响应期限为 12,000 ms，可配置。到期报告超时并关闭该连接，不在可能收到迟到响应的连接上继续发送。
- 两种服务端每次开始等待下一条完整请求时启动期限，默认 30,000 ms，可配置。零星字节不重置完整请求期限；超时关闭连接并清理资源。
- 读取期限不计入已接收请求的业务执行时间；正常 delay 不应被默认配置误判。
- 异步服务端必须同时服务多个连接：A 等待 delay 时，B 的 ping 应在 A 的响应前到达。
- Ctrl-C 后停止接受新连接，及时结束等待输入的连接，不开始下一条请求。
- 在途请求可在整体退出宽限内完成；默认宽限 2,000 ms，可配置，从收到信号开始计时，不因进展重置。
- 宽限用尽后取消并回收剩余任务，释放连接，再退出。被取消请求的客户端可能看到 EOF。
- 单连接错误不得终止其他连接或整个服务端；已结束任务需要及时回收。
- 同步服务端不要求异步任务管理；全部项目应可用 Ctrl-C 结束进程。

参数命名可自行选择，在 README 中说明。推荐端口、响应期限、读取期限和退出宽限分别配置；测试可使用短时间值。

协议互通验证使用[通用参考程序](../../reference/README.md)，只验收上面三个动作；参考程序的其他动作不属于本项目任务。
