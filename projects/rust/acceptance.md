# Rust 验收清单

按[协议](protocol.md)验证。基线只承诺单连接一条 ping 交互，后续逐步达到完整行为。

| 阶段 | 验收内容 |
|---|---|
| 基线 | 三个项目分别通过测试与静态检查，同步客户端可连接两种服务端 |
| 客户端 | 构造 echo/delay；连续交互；显示错误；连接失败不崩溃；与参考服务端互通 |
| 同步服务端 | 三个动作、字段与范围检查、连续请求、非法 JSON、未知动作、超长行和断开 |
| 异步服务端 | 完整协议与同步版本一致；跨连接并发；单连接错误隔离 |
| 超时与退出 | 响应期限、完整请求期限、任务清理、空闲连接结束、在途请求宽限与取消；Clap 参数与帮助信息 |
| 配置与日志 | 地址可配置；输出启动地址、连接建立/结束和处理失败原因；超时与退出阶段记录对应结果 |
| 回归 | 修改后原有动作、错误处理和独立项目检查仍成立 |

## 连续交互与边界

在同一连接发送合法 ping、非法 JSON、合法 echo，分别得到响应并保持连接。测试 LF/CRLF、半条消息后断开、完整 JSON 缺少行尾换行后 EOF、非法 UTF-8 后继续发送合法请求、消息长度上限、错误 id 类型、未知动作及额外字段。逐步更新基线中“一条消息后关闭”的测试以匹配新的连续交互行为。

## 并发

1. 确认服务端已经监听；客户端 A 发送 2000 ms 的 delay。
2. 确认 A 已发出完整请求且尚未返回，再由独立连接 B 发送 ping。
3. 在本机正常负载下，B 在 1000 ms 内返回，且先于 A 返回；A 的 delay 不能提前完成（允许 100 ms 计时误差）。
4. 重复测试 A 中途断开，确认 B 和服务端后续连接仍正常。

测试需记录请求发送与响应时间、设置总等待上限。若系统负载使时间判断不可靠，记录环境并重复验证，不能只看最终两条请求都成功。

## 参数和日志

完成“超时与退出”阶段后，三个程序使用 Clap 管理参数：客户端配置连接地址和响应期限；同步服务端配置监听地址和读取期限；异步服务端另有退出宽限。默认值遵循协议，`--help` 说明参数含义和单位；非法参数给出明确提示并退出。

启动时输出实际监听地址；服务端记录连接建立、结束及处理失败的原因。实现超时和退出时，增加对应事件与处理结果。日志格式和日志库自行选择。

## 生命周期

- 将服务端读取期限设为 200 ms：不发消息、只发半条消息、间隔发送零星字节，均不能无限占用连接。
- 用不会响应的本地测试对端验证客户端响应超时和关闭连接。
- 合法 delay 在默认配置下正常完成，不被读取期限提前中断。
- 同时保持空闲连接与执行中的 delay，再发 Ctrl-C：空闲连接及时关闭，不接受新请求。
- 宽限大于剩余处理时间时允许返回；宽限小于剩余时间时取消任务并结束，退出不能无限等待。
- 多次短连接后检查已完成任务不会持续堆积；一条连接失败不结束服务进程。

使用参考程序验证协议，超时等故障场景可编写专用测试对端。
