# 验收清单

## 项目范围

按[公共任务说明](tasks.md#路线与层级)确定完成范围。本清单组织验证场景，接口、数值边界和生命周期要求以[协议](protocol.md)为准，两条路线共用。

## 起始代码

按[起始能力](tasks.md#起始能力)运行项目测试与 baseline 自查，区分基线检查和下面的最终验收。

## 第一层：客户端

- 客户端能完成全部接口操作，支持终端多行文本输入，并说明如何结束输入。
- 显示 HTTP 状态及结果，遇到 401 提示重新登录；网络失败后仍能继续操作或明确退出。
- echo 保留 Unicode、换行和空文本；delay 校验类型、范围并实际等待。
- 客户端总操作期限按下文的边界和生命周期场景单独验证。

使用[参考服务端](reference-programs.md)验证客户端，不要只用手工打印请求判断成功。

## 第二层：同步服务端（可选）

- 服务端能完成基础路由和账号流程，注册同名用户只能有一次成功。
- 上传、覆盖、读取、排序列表、删除行为符合协议，缺失文本返回 404。
- 两个用户保存同名文本互不影响，不能访问对方文本。
- 注销清理账号、文本和令牌，同名重新注册为空账号。
- 检查名称边界、UTF-8 字节上限、非法 JSON、字段类型及重复注册。
- `delay` 等待完成才返回结果；同步服务端按顺序处理请求。

可以使用自己的客户端或完整参考客户端验证同步服务端。

## 第三层：异步服务端

- 异步服务端完成同步服务端要求的业务行为。
- 异步端的 delay 不阻塞其他连接的 ping。
- 并发同名注册只成功一次；登录、文本修改和注销竞争时状态仍一致。
- 密码计算等阻塞工作不能占用事件循环，状态锁期间不能等待网络或 delay。
- 在并发请求下执行下文的边界和生命周期验证。

可以使用自己的客户端或完整参考客户端验证异步服务端。

## 服务端后段：令牌过期

- 用 `--token-ttl-seconds 2` 启动服务端：登录响应包含 `expires_in`，期限前可使用，到期返回 401。
- 期间发请求不会续期；重新登录后新令牌有效、旧令牌无效。
- 退出和注销同样撤销令牌，注销后同名重新注册为空账号。

## 边界和生命周期

- 按[协议期限](protocol.md#运行与并发)验证客户端总操作期限和服务端请求读取总期限；持续小块发送也不能延长期限。
- 对两个服务端分别检查空闲、读取部分请求、执行 delay、发送响应时的 Ctrl-C 行为，确认停止接收请求，并在协议规定的期限内结束在途处理、退出。
- 单个请求失败不影响其他请求；没有遗留后台任务或无限等待。

[阶段自查](self-check.md)覆盖常见场景，不代替完整验收。补充自己的测试，说明验证方法与已知限制。文档要求见[成果说明](deliverables.md)。
