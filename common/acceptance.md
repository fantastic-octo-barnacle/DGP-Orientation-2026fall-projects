# 验收清单

## 项目范围

按[公共任务说明](tasks.md#路线与层级)确定完成范围。本清单组织验证场景，接口、数值边界和运行要求以[协议](protocol.md)为准，两条路线共用。根据下面的场景自行选择验证方法，不要求采用参考程序的内部实现方式。

## 起始代码

按[起始能力](tasks.md#起始能力)运行项目测试与[共通交互](tasks.md#共通交互)，区分起始行为和下面的最终验收。

## 第一层：客户端

- 客户端能完成全部接口操作，支持终端多行文本输入，并说明如何结束输入。
- 显示 HTTP 状态及结果，遇到 401 提示重新登录；网络失败后仍能继续操作或明确退出。
- echo 保留 Unicode、换行和空文本；分别尝试立即结束输入、保留末尾换行、在正文中输入与结束标记相同的内容，确认输入约定无歧义。
- 暂停或关闭对端后发起操作，确认连接失败或库报告超时时能显示错误，并继续操作或明确退出；记录客户端使用的超时配置。

使用[参考服务端](reference-programs.md)验证客户端，不要只用手工打印请求判断成功。

## 第二层：同步服务端（可选）

- 服务端能完成基础路由和账号流程，注册同名用户只能有一次成功。
- 上传、覆盖、读取、排序列表、删除行为符合协议，缺失文本返回 404。
- 两个用户保存同名文本互不影响，不能访问对方文本。
- 注销清理账号、文本和令牌，同名重新注册为空账号。
- 旧账号的登录尚未完成时注销账号并同名重注册，旧登录不能作用于新账号；不限定实现中如何区分两次注册。
- 检查名称边界、UTF-8 字节上限、非法 JSON、字段类型及重复注册。
- 使用同步业务代码实现接口，并在并发请求下保护共享状态。

可以使用自己的客户端或完整参考客户端验证同步服务端。

## 第三层：异步服务端

- 异步服务端完成同步服务端要求的业务行为。
- 并发同名注册只成功一次；登录、文本修改和注销竞争时状态仍一致。
- 密码计算等阻塞工作不能占用事件循环，状态锁期间不能等待网络。
- 在并发请求下执行下文的边界和错误恢复验证。

可以使用自己的客户端或完整参考客户端验证异步服务端。

## 服务端后段：令牌过期

- 用 `--token-ttl-seconds 2` 启动服务端：登录响应包含 `expires_in`，期限前可使用，到期返回 401。
- 期间发请求不会续期；重新登录后新令牌有效、旧令牌无效。
- 退出和注销同样撤销令牌，注销后同名重新注册为空账号。

## 边界和错误恢复

- 发送非法 JSON、错误字段或超限文本后，再发合法请求，确认错误不会破坏服务端状态或使其他请求失败。每次只引入一个待验证的错误，不比较多个错误同时存在时的返回顺序。
- 用两个账号保存同名文本，交错执行读取、覆盖和删除，确认数据隔离；并发注册相同用户名时只能有一次成功。
- 运行客户端、服务端并正常交互后，检查 `q` 或 Ctrl-C 能按程序、框架的常规方式结束运行。网络超时、连接和退出使用[协议说明](protocol.md#运行与并发)中的常规机制，不验证精确秒数或逐字节发送时序。

结合项目测试、客户端与参考程序完成上述验证，说明验证方法与已知限制。文档要求见[成果说明](deliverables.md)。
