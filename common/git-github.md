# Git 与 GitHub 共通指引

所有人都需要完成本指引中的基础练习和自检，包括已经使用过 Git/GitHub 的同学。目标是理解文件修改如何进入本地提交历史，再同步到远程仓库。

练习使用 README、学习笔记等 Markdown 文件即可，可以直接在通过模板创建的个人仓库中完成。

## 准备与资料

- 从 [Git 官方网站](https://git-scm.com/downloads)安装 Git，确认能查看版本。已安装者直接使用现有环境。
- 准备可登录的 GitHub 账号，阅读 [GitHub 入门文档](https://docs.github.com/en/get-started)。
- 概念查阅 [Pro Git 中文版](https://git-scm.com/book/zh/v2)，重点阅读基础与远程仓库部分。

## 基础练习

1. 按[仓库首页](../README.md)通过模板创建个人仓库，并克隆到本地。
2. 分几次修改 README 或学习笔记，观察 `status` 与 `diff`，选择变化进入暂存区，再形成能说明目的的提交。
3. 将本地提交推送到 GitHub，再从另一个目录克隆仓库，检查文件和提交历史。
4. 分别从本地与 GitHub 修改文档，练习 `push` 和 `pull`，理解冲突产生的原因。
5. 建立临时目录并用 `.gitignore` 排除，解释它为何不影响已跟踪文件。

完成后可继续练习分支、合并和一次可控冲突。学习重点是提交、同步和忽略规则；具体命令可自行查阅资料。操作前先确认工作目录、未提交变化和命令作用。

## 自检与项目应用

完成练习后，确认自己能解释以下问题：

- 工作目录、暂存区、本地提交和远程仓库分别是什么？
- `commit` 与 `push` 有什么区别？
- `clone` 会取得哪些文件和历史？
- 为什么忽略规则不能删除已有历史？

在后续项目中持续使用这些操作，保留自然的迭代历史。提交前检查差异，用忽略规则排除虚拟环境、`target` 和缓存，并将令牌及个人凭证保存在仓库外。遇到失败时记录命令、工作目录、原始报错及已验证的假设。

共通练习通过实际操作和自检完成，不另交截图或练习仓库。项目材料按[成果说明](deliverables.md)整理。
