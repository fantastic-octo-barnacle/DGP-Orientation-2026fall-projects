# 公共任务说明

## 路线与层级

Python 和 Rust 是两条等价路线，只需选择一条。两者的任务、协议、验收要求与最终行为相同，区别在于语言、工具链和起始代码采用的库。运行方式分别见 [Python](../projects/python/README.md) 和 [Rust](../projects/rust/README.md)。

推荐大一没有编程经验的候选人选择 Python 路线，大一有编程经验或大二及以上的候选人选择 Rust 路线。两条路线都要求候选人自学缺少的知识，补齐功能、测试和说明。

| 层级 | 目录 | 完成要求 |
| --- | --- | --- |
| 同步客户端 | `client-sync/` | 必做，完成交互式 HTTP 客户端。 |
| 同步服务端 | `server-sync/` | 可选过渡层，可先学习同步业务处理，也可直接进入异步服务端。 |
| 异步服务端 | `server-async/` | 必做，完成业务行为及异步并发处理。 |

同步服务端和异步服务端的业务要求完全一致，而后者的难点在于掌握异步编程的语法要求、理解异步操作的行为和本质。你可以根据自己的能力选择是否完成同步服务端，或直接跳过它。

## 起始能力

以下状态适用于两条语言路线；“已实现”指起始代码已有该能力，候选人扩展时仍须保持其行为。

- **已实现**：客户端命令循环、HTTP 请求与 JSON 响应处理、状态与结果显示、登录令牌保存、401 提示与令牌清理、网络失败后继续操作。
- **已实现**：服务端 `GET /ping`、`POST /users`、`DELETE /sessions/current`；账号字段校验、密码处理、令牌生成与共享状态保护。异步服务端已有将阻塞业务移出事件循环的示范。
- **部分实现**：`POST /sessions` 已能登录并替换旧令牌；候选人须增加令牌过期、`expires_in` 和 `--token-ttl-seconds`。
- **部分实现**：`GET /texts` 已按当前用户返回排序列表；起始代码无法写入文本，列表为空，候选人须结合文本增删验证它。
- **待实现**：客户端和服务端的 `POST /echo`、`DELETE /users/me`、`PUT /texts/{name}`、`GET /texts/{name}`、`DELETE /texts/{name}`，以及客户端多行文本输入。起始服务端尚未提供这些路由，客户端对应命令提示待完成。
- **待补齐或验证**：扩展后的输入边界、用户间文本隔离、并发一致性和常见网络错误后的恢复，以及相关测试。

可以直接沿用起始项目的 HTTP 库和框架，通过其配置与常规错误处理完成网络交互和退出；无需另写底层连接管理或精确计时逻辑。学习重点是业务行为、共享状态和异步处理。

先运行所选独立项目的测试，再按[共通交互](#共通交互)验证起始行为。随着任务完成，更新只适用于起始状态的测试断言。

## 任务顺序

各项任务开始前，先按照 [Python](../projects/python/README.md) 或 [Rust](../projects/rust/README.md) 配置工具链、理解开发工作流。

各项任务按下面的小任务逐步推进，每步完成后**补充测试并验证结果**。请求字段、响应体、状态码和边界以[协议](protocol.md)为准。

### 同步客户端

1. **验证已有流程**：运行 `GET /ping`、`POST /users`、`POST /sessions`、`GET /texts` 和 `DELETE /sessions/current`。确认能显示 HTTP 状态及结果，登录后保存令牌并用于受保护请求，退出后清除本地令牌。
2. **实现回显与文本输入**：补齐 `POST /echo`，将输入放入 `text` 字段；支持 Unicode、空字符串和终端多行输入，并说明如何结束输入。检查空文本、末尾换行和与结束标记相同的正文行都能表达，输入约定自行选择。确认响应文本与输入一致，为输入处理和请求构造补充测试。
3. **实现上传与读取**：补齐 `PUT /texts/{name}` 和 `GET /texts/{name}`，读取用户输入的名称、文本并携带登录令牌。确认上传后可读回原文，同名再次上传后读回新内容。
4. **实现删除并验证列表**：补齐 `DELETE /texts/{name}`，结合已有 `GET /texts` 检查上传、删除后的列表变化。确认名称按序显示，获取或删除不存在的文本时能显示 404。
5. **实现账号注销**：补齐 `DELETE /users/me`，成功后清除本地令牌。确认旧令牌无法再访问文本，同名重新注册、登录后列表为空。
6. **验证失败与退出**：为响应处理补充测试；确认 401 会提示重新登录并清除令牌，错误体缺失或不是 JSON 时仍能显示 HTTP 状态。使用 HTTP 库提供的有限超时，连接失败或超时后能继续操作或明确退出；检查 `q` 和常规 Ctrl-C 退出，记录使用的超时配置。见[运行要求](protocol.md#运行与并发)。

使用[参考服务端](reference-programs.md)验证真实交互。

### 同步服务端

这一层可选；选择完成时，使用同步业务代码依次完成以下任务。每步补充业务与 HTTP 测试，并从实现业务时就保护共享状态；同步业务处理不代表请求串行执行。

起始项目提供同步的业务、应用组装、启动与 HTTP 测试接口，完成本层全部任务无需编写 `async/await`。底层 HTTP 适配可以使用异步框架，集中在无需修改的基础设施模块中；新增路由、业务配置和令牌过期均在同步代码中完成。各语言的文件入口见对应启动说明。异步服务端仍显式学习异步请求处理与阻塞工作隔离。

1. **验证已有账号流程**：检查 `GET /ping`、`POST /users`、`POST /sessions`、`DELETE /sessions/current` 和 `GET /texts`。确认重复注册返回 409、错误凭据返回 401、再次登录使旧令牌失效、退出使当前令牌失效；令牌过期在第 6 步补齐。
2. **实现回显与输入校验**：补齐 `POST /echo`，原样返回 `text`。确认 Unicode、换行和空文本可往返；非法 JSON、缺失或多余字段、错误类型返回 400，文本或请求体超限返回 413。
3. **实现文本上传与读取**：补齐 `PUT /texts/{name}` 和 `GET /texts/{name}`，根据令牌确定用户，校验名称与文本，仅访问该用户的数据。确认创建、同名覆盖和读取一致；无效身份返回 401，不存在的文本返回 404。
4. **实现删除、验证列表与隔离**：补齐 `DELETE /texts/{name}`，结合已有 `GET /texts` 验证名称升序、删除后移除名称、空列表及重复删除返回 404。使用两个用户保存同名文本，确认读、写、列出和删除均互不影响。
5. **实现账号注销**：补齐 `DELETE /users/me`，一起清理当前用户、全部文本和令牌。确认旧令牌失效，同名重新注册后无旧数据，注销完成后旧身份的并发操作不能重新写入文本。还要考虑旧账号的登录尚在处理、账号已注销并同名重注册的情况：旧登录不能作用于新账号。
6. **增加令牌过期**：实现 `--token-ttl-seconds`，为 `POST /sessions` 的成功响应补充 `expires_in`，并在所有受保护接口检查有效期。按[用户与身份规范](protocol.md#用户与身份)验证到期返回 401、操作不续期、重新登录替换令牌，以及退出和注销仍能撤销令牌。
7. **完成边界、并发与错误恢复验证**：按[错误响应](protocol.md#错误响应)检查各接口及未知路径、不支持的方法；按[运行与并发要求](protocol.md#运行与并发)验证同名注册竞争、文本操作与登录替换或注销竞争时的状态一致性。确认单个请求失败后其他请求仍能成功，并使用框架的常规方式处理连接和 Ctrl-C 退出。

### 异步服务端

按照[同步服务端](#同步服务端)的全部 7 项要求完成接口和测试，但使用异步请求处理与等待；跳过同步层时，也须在这一层完成这些任务。

- 密码计算等阻塞工作须移出事件循环或异步运行时工作线程；起始代码已有示范，扩展时保持这一边界，不能只把函数改成 `async`。
- 共享状态仍须保护；鉴权与数据操作保持一致，不在持锁期间等待网络。
- 在并发请求下验证业务结果和错误恢复，网络连接、超时与退出沿用框架机制。

两个服务端层级均可使用自己的客户端或[参考客户端](reference-programs.md)验证。它们分别启动、各自持有独立的内存数据，不需要互相同步。

### 收尾与交付

令牌过期、边界、并发与错误恢复已列入上述服务端第 6、7 步。完成功能与测试后，按本节收尾：

- 保留自然的 Git 提交历史，让读者能够看出实现、测试和修正的过程；不要把所有改动压成一次无法追溯的提交。
- 在所选项目说明中写清运行入口、必要参数、测试方法和结果；接口行为可以引用[协议](protocol.md)，并注明已实现范围和自行扩展。
- 说明实际完成的层级。若跳过同步服务端，写明原因和最终选择的路线。
- 记录已知问题、未实现行为、依赖的框架默认值和只在特定环境验证过的结论。
- 使用[学习自查](self-check.md)复盘关键概念；若使用 AI 或参考资料，须能解释并验证采用的代码。

## 共通交互

按语言入口启动一个服务端和客户端，地址、端口以启动参数为准。两个服务端使用同一端口时应依次运行，以 Ctrl-C 停止当前服务端。

在客户端输入 `ping`，应看到 200 和 pong；再使用 `register`、`login`、`list`、`logout`，按提示输入必要信息。初始文本列表为空，输入 `q` 退出。任务命令的输入方式可以完善，但须在自己的运行说明中解释。
