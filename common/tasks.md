# 公共任务说明

## 路线与层级

Python 和 Rust 是两条等价路线，只需选择一条。两者的任务、协议、验收要求与最终行为相同，区别在于语言、工具链和起始代码采用的库。运行方式分别见 [Python](../projects/python/README.md) 和 [Rust](../projects/rust/README.md)。

| 层级 | 目录 | 完成要求 |
| --- | --- | --- |
| 同步客户端 | `client-sync/` | 必做，完成交互式 HTTP 客户端。 |
| 同步服务端 | `server-sync/` | 可选过渡层，可先学习顺序请求处理，也可直接进入异步服务端。 |
| 异步服务端 | `server-async/` | 必做，完成业务行为及异步并发处理。 |

跳过同步服务端不会减少客户端或异步服务端的要求。在[成果说明](deliverables.md)中说明实际完成范围及跳过原因。

## 起始能力

起始代码提供客户端命令循环、HTTP 请求与 JSON 响应处理，以及服务端的 ping、注册、登录、退出登录和空文本列表。服务端已示范密码处理、令牌生成和状态保护；登录替换旧令牌，但令牌暂不过期。

`echo`、`delay`、注销账号和单篇文本的上传、获取、删除仍待实现。服务端对应路由返回 501，客户端对应命令提示待完成。登录响应尚无 `expires_in`，服务端尚不接受 `--token-ttl-seconds`。完整请求期限与有界退出也需要补齐或验证。

先运行所选独立项目的测试，再运行[阶段自查](self-check.md)中的 baseline。随着任务完成，更新只适用于起始状态的测试断言；501 不是最终行为要求。

## 任务顺序

### 同步客户端

补齐[协议](protocol.md)中的所有操作，处理令牌、401 响应、网络失败和退出。支持 Unicode、空文本及终端多行输入，并说明如何结束输入；显示 HTTP 状态和结果。遵守协议的总操作期限，为请求构造、响应处理和用户输入补充测试。

使用[参考服务端](reference-programs.md)验证真实交互。

### 同步服务端

选择完成这一层时，补齐业务路由、输入校验、账号与令牌状态、用户间文本隔离，以及错误响应。按协议顺序处理请求，编写业务与 HTTP 测试。

### 异步服务端

完成相同的服务端业务行为，并满足[协议中的并发与生命周期约束](protocol.md#运行与并发)。重点检查异步等待、共享状态、阻塞工作的处理方式和退出过程。起始代码已有将同步业务移出事件循环的示范，扩展功能时仍需维持这一边界。

两个服务端层级均可使用自己的客户端或[参考客户端](reference-programs.md)验证。它们分别启动、各自持有独立的内存数据，不需要互相同步。

### 服务端后段与收尾

基础业务完成后，按[用户与身份规范](protocol.md#用户与身份)增加令牌过期配置、登录响应字段和有效性检查。随后补充输入边界、期限、退出、错误处理和测试，使用[验收清单](acceptance.md)完成验证并整理[成果说明](deliverables.md)。

## 共通交互

按语言入口启动一个服务端和客户端，地址、端口以启动参数为准。两个服务端使用同一端口时应依次运行，以 Ctrl-C 停止当前服务端。

在客户端输入 `ping`，应看到 200 和 pong；再使用 `register`、`login`、`list`、`logout`，按提示输入必要信息。初始文本列表为空，输入 `q` 退出。任务命令的输入方式可以完善，但须在自己的运行说明中解释。
