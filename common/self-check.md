# 学习自查

本文档提供一些示例问题以供读者自查对工程开发、业务逻辑的理解程度。本文档也可看作面试问题的示例，但不代表最终面试的实际范围。

## 工具链与项目结构

- 你使用的检查、测试和运行命令分别做了什么？依赖声明和锁文件分别解决什么问题？
- 新增依赖或模块后，哪些文件会变化？为什么这些变化需要一起提交？
- 业务代码、HTTP 适配和测试为什么放在不同文件或模块中？如果交换它们的职责，会带来什么影响？

## Git 与开发过程

- 一个提交应该包含多小的改动？你的提交历史能否让读者看出实现、验证和修正的过程？
- 提交前你会做哪些检查？如果某次提交引入了问题，如何定位和回退？
- 阅读别人的项目时，你会先看哪些文件来判断入口和依赖？

## HTTP 与客户端

- 一个 HTTP 请求和响应分别包含哪些基本信息？为什么用状态码判断成败，而不是只看响应体？
- 登录令牌存在哪里？收到 401 后客户端为什么要清理或要求重新登录？
- 多行文本如何区分正文和结束标记？空文本、末尾换行和包含结束标记的文本如何表达？
- 连接失败或超时后，客户端为什么还能继续操作？超时值应该在什么地方说明？

## 身份、状态与数据隔离

- 为什么文本所属用户由服务端根据令牌确定，而不是由客户端传参指定？
- 登录、再次登录、退出、注销和令牌过期分别对旧令牌产生什么影响？
- 注销为什么必须同时清理用户、文本和令牌？同名重新注册为什么不能继承旧数据？
- 两个用户保存同名文本时，哪些操作必须互相隔离？

## 并发与共享状态

- 同步服务端中，为什么“业务代码是同步的”不等于请求会串行执行？
- 哪些数据会被多个请求同时访问？你的实现用什么方式保护它们？
- 两个请求同时注册同名用户、同时覆盖同一篇文本、登录和注销交错时，最终状态应该是什么？
- 旧账号登录尚未完成时账号被注销并同名重注册，为什么旧登录不能作用于新账号？

## 异步与阻塞

- `async`/`await` 在当前项目中改变了什么？把函数标记为异步是否自动解决阻塞？
- 密码计算为什么不能占用事件循环？阻塞工作应放在哪里？
- 等待网络 I/O 时持有状态锁可能造成什么问题？如何避免？
- 如何构造并发请求验证异步服务端的行为？

## 测试与验证

- 每个测试分别在证明什么？删除某个测试后会失去什么保障？
- 业务测试和 HTTP 测试有什么区别？为什么有些问题必须通过完整请求验证？
- 参考程序在你的验证中承担什么角色？它为什么不能替代你自己的测试？
- 验证错误输入时，为什么每次只改变一个条件？

## 路线补充问题

### Python

- `uv sync --locked`、`.venv/`、`pyproject.toml` 和 `uv.lock` 之间是什么关系？
- `uv run` 为什么能使用项目环境中的工具？`ruff` 来自哪里？
- 同步测试中的 `TestClient` 和异步运行时各自模拟了什么？

### Rust

- `Cargo.toml` 和 `Cargo.lock` 的职责有什么不同？`--locked` 避免什么问题？
- crate、module 和当前项目的文件组织有什么关系？
- Rust 异步运行时、`async fn` 和阻塞调用之间的边界是什么？
