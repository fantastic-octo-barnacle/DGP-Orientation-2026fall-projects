# 学习自查

本文档提供一些示例问题，供读者自查对工程开发流程、语言工具链、依赖管理和业务逻辑的理解程度。本文档不提供答案或提示，也不要求提交自查结果；需要查证时，请回到项目文档和官方资料。本文档也可看作面试问题的示例，但不代表最终面试的实际范围。

## 环境、工具链与依赖

- 开始任务前，你会检查哪些运行时和工具的版本？如何确认本机环境满足当前路线的要求？
- 每个任务目录为什么各自维护依赖和运行环境？如果在另一个任务目录或全局环境中运行命令，可能出现什么问题？
- `pyproject.toml` / `Cargo.toml` 和锁文件分别记录什么？为什么新增或修改依赖时，两者需要一起提交？
- `uv sync --locked` 或 Cargo 的 `--locked` 在保护什么？清单和锁文件不一致时，应该修改哪一边，为什么不能绕过检查？
- 新增一个直接依赖后，锁文件、构建结果和可运行环境分别会发生什么变化？间接依赖为什么也需要被记录？
- pytest、ruff、pyright 或 Clippy、rustfmt 等工具从哪里获得？为什么不能依赖机器上碰巧安装的版本？
- 检查、测试和运行命令分别能发现哪类问题？只执行其中一条可能漏掉什么？
- `.venv/`、`target/`、缓存和构建产物为什么要排除在提交之外？怎样从干净 clone 得到可复现的环境？
- 业务代码、HTTP 适配和测试分别放在哪里？如果交换或混合这些职责，定位问题和修改实现会变得多困难？

## 开发工作流与 Git

- 拿到一个不熟悉的任务目录时，你会先读什么、先运行什么？如何确认起始状态和已有能力？
- 一个提交应该包含多小的改动？怎样判断它既完整到可以独立验证，又没有混入无关修改？
- 提交信息应该说明什么？为什么只写“修改”“更新”会让后续排查更困难？
- 提交前你会检查哪些内容？工作区、暂存区、差异和测试结果分别要确认什么？
- 工作目录、暂存区、本地提交和远程仓库之间是什么关系？`commit` 与 `push` 的区别是什么？
- `.gitignore` 解决什么问题？环境、缓存、构建产物和凭证应如何排除？为什么加入忽略规则不会删除历史中的文件？
- 如果某次提交引入了问题，如何定位并回退？`revert`、新增修复提交和重置历史分别适合什么场景？
- 调试时如何从完整报错出发，构造最小复现、验证假设并确认修复？什么时候应该补一个回归测试？
- 使用官方文档、AI 或示例代码时，怎样确认它适用于当前版本和项目约束？哪些代码不应该未经理解就提交？

## 协议与行为边界

- 一个 HTTP 请求和响应分别包含哪些基本信息？客户端应如何结合状态码和响应体判断结果？
- 登录令牌保存在哪里？收到 401、令牌过期、退出或注销后，客户端应如何处理本地状态和后续请求？
- 为什么文本所属用户必须由服务端根据令牌确定，而不能由客户端传入用户标识？
- 注销用户时为什么必须同时清理用户、文本和令牌？同名重新注册为什么不能继承旧数据？

## 并发与异步

- 服务端有哪些共享状态会被多个请求同时访问？哪些数据必须按用户隔离？你用什么机制保护它们？
- 两个请求同时注册同名用户、同时覆盖同一篇文本、登录与注销交错，或旧登录尚未完成时账号已注销并同名重注册，最终状态应该是什么？你如何验证不会出现中间态？
- `async`/`await` 在当前项目中改变了什么？只把函数标记为异步，为什么不能自动解决阻塞问题？
- 密码计算等阻塞工作应放在哪里？如果直接在事件循环或异步运行时线程中执行，会有什么后果？
- 等待网络 I/O 时持有状态锁可能造成什么问题？如何调整锁的范围或操作顺序来避免？

## 测试与验证

- 每个测试分别在证明什么？删除某个测试后会失去什么保障？
- 业务测试和 HTTP 测试有什么区别？为什么有些行为必须通过完整请求验证？
- 参考程序在你的验证中承担什么角色？它为什么不能替代你自己的测试？

## 路线补充问题

### Python

- 从干净 clone 到运行测试，`uv sync --locked`、`uv run` 和激活后的 `.venv` 分别做了什么？为什么不应改用全局 `pip` 安装依赖？
- `ruff`、`pytest` 和 `pyright` 从哪里获得？如果机器上恰好安装了其他版本，可能造成什么差异？
- 同步测试中的 `TestClient`、异步服务端和 `asyncio.to_thread` 分别执行或模拟了什么？它们的并发行为有什么不同？

### Rust

- 从干净 clone 到运行测试，`cargo test --locked` 如何解析 `Cargo.toml`、`Cargo.lock` 和本地缓存？为什么不应复用另一个任务目录的 `target/`？
- crate、module 和当前项目的文件组织是什么关系？为什么把业务逻辑放在 `lib.rs` 比全部写进 `main.rs` 更利于测试？
- Rust 异步运行时、`async fn` 和 `spawn_blocking` 之间是什么边界？阻塞调用为什么不能只靠加上 `async` 解决？
