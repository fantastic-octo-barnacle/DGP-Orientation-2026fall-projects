# 项目成果说明

整理所选项目的成果，另一项目保持起始状态即可。

个人仓库应保留：

- 源码、测试、项目清单、锁文件与必要配置。
- 所选项目的运行与成果说明：环境、启动方式、检查方法、已完成能力、已知问题。保留原任务书，在项目 README 中添加个人成果章节和最新运行方法，或链接独立的成果文档。
- 自然的 Git 提交历史，以及起始代码来源。
- 简短学习记录，例如 `PROGRESS.md`，记录关键问题、假设、验证结果和下一步。

说明成果时，明确区分起始代码已有功能和个人新增修改，如实列出通过与失败的检查、未完成项及定位过程。

可以查阅资料、搜索、使用 AI、讨论和求助。理解并验证最终采用的代码，对外部代码或关键建议记录来源与自己的处理，准确说明个人完成的工作。

保持已有正常功能可运行，为新增功能编写测试。公开自查只覆盖少量样例，还需要对照所选项目的验收清单验证边界和异常情况。

共通任务不另交截图、日志或练习仓库。

CI 是可选扩展：可自行研究并编写 workflow，在干净环境中执行所选项目的检查。

可将[个人成果模板](result-template.md)复制为所选项目的 `RESULTS.md`，按需调整，并从项目 README 链接。
