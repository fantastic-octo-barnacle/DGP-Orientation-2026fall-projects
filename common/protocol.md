# HTTP 用户文本服务协议

使用 HTTP/1.1，默认地址 `http://127.0.0.1:7878`。请求体和成功响应为 UTF-8 JSON，携带 `Content-Type: application/json`。HTTP 库负责编码和分帧。

成功响应为 `{"data": ...}`。失败由 HTTP 状态码表示，响应体可带 `{"message": "原因"}`；说明文字不要求一致。请求不含自定义 id，错误不含自定义 code。

本文定义最终行为；起始能力与任务顺序见[公共任务说明](tasks.md)，验证方法见[验收清单](acceptance.md)。

## 接口

请求 JSON 对象中的字段均必填，只允许列出的字段，类型不自动转换；“无请求体”表示客户端不发送请求体。成功响应统一包在 `data` 字段中，以下示例均展示完整 JSON 响应体。字段范围见[用户与身份](#用户与身份)和[文本与输入边界](#文本与输入边界)，通用错误见[错误响应](#错误响应)。

示例按顺序执行，省略公共 HTTP 头；带请求体时发送 `Content-Type: application/json`。受保护接口还须发送 `Authorization: Bearer <token>`，其中 `<token>` 替换为最近一次登录取得的令牌；假定执行期间令牌未过期。

### `GET /ping`：连通性检查

公开，无请求体。成功为 200，`data` 固定为字符串 `"pong"`。

请求 `GET /ping` → 200，响应 `{"data":"pong"}`。

### `POST /users`：注册

公开。请求为对象，包含字符串 `username`、`password`。成功为 201，`data` 为仅含字符串 `username` 的对象，值为注册的用户名；注册不会自动登录。字段不合法返回 400，用户名已存在返回 409。

请求 `POST /users`，体 `{"username":"alice","password":"password1"}` → 201，响应 `{"data":{"username":"alice"}}`。

### `POST /sessions`：登录

公开。请求为对象，包含字符串 `username`、`password`，字段范围与注册相同。成功为 200，`data` 为包含字符串 `token` 和正整数 `expires_in` 的对象；前者用于后续鉴权，后者为配置的有效秒数。登录替换该用户的旧令牌。字段不合法返回 400，格式合法但用户名不存在或密码错误返回 401。

请求 `POST /sessions`，体 `{"username":"alice","password":"password1"}` → 200，响应 `{"data":{"token":"<token>","expires_in":300}}`（默认有效期，令牌值仅为占位）。

### `POST /echo`：回显文本

公开。请求为仅含字符串 `text` 的对象。成功为 200，`data` 为输入文本本身，保留 Unicode、换行和空字符串。字段不合法返回 400，文本或请求体超限返回 413；空文本也须提交 `{"text":""}`。

请求 `POST /echo`，体 `{"text":"你好\nRM"}` → 200，响应 `{"data":"你好\nRM"}`。

### `PUT /texts/{name}`：上传或覆盖文本

需要鉴权。路径参数 `name` 为文本名称，请求为仅含字符串 `text` 的对象。成功为 200，`data` 为 `null`；不存在则创建，同名则覆盖当前用户的文本。名称或字段不合法返回 400，身份无效返回 401，文本或请求体超限返回 413。

请求 `PUT /texts/note`，体 `{"text":"你好\nRM"}` → 200，响应 `{"data":null}`。

### `GET /texts`：列出文本

需要鉴权，无请求体。成功为 200，`data` 为当前用户的文本名称字符串数组，按名称升序排列，无文本时为 `[]`。身份无效返回 401。

请求 `GET /texts` → 200，响应 `{"data":["note"]}`。

### `GET /texts/{name}`：获取文本

需要鉴权，无请求体，路径参数 `name` 为文本名称。成功为 200，`data` 为当前用户保存的完整文本字符串，可能为空。名称不合法返回 400，身份无效返回 401，当前用户没有该文本返回 404。

请求 `GET /texts/note` → 200，响应 `{"data":"你好\nRM"}`。

### `DELETE /texts/{name}`：删除文本

需要鉴权，无请求体，路径参数 `name` 为文本名称。成功为 200，`data` 为 `null`。名称不合法返回 400，身份无效返回 401，当前用户没有该文本返回 404。

请求 `DELETE /texts/note` → 200，响应 `{"data":null}`。

### `DELETE /sessions/current`：退出登录

需要鉴权，无请求体。成功为 200，`data` 为 `null`，当前令牌立即撤销。身份无效返回 401，重复使用已撤销令牌退出也返回 401。

请求 `DELETE /sessions/current` → 200，响应 `{"data":null}`。

### `DELETE /users/me`：注销账号

需要鉴权，无请求体。成功为 200，`data` 为 `null`，删除当前用户、其全部文本和令牌。身份无效返回 401。

重新登录取得新令牌后，请求 `DELETE /users/me` → 200，响应 `{"data":null}`。

## 用户与身份

用户名区分大小写，由 1–32 个 ASCII 字母、数字、下划线或连字符组成。密码为 8–128 个 Unicode 字符。重复注册返回 409，用户名或密码错误统一返回 401。

注册后需要登录。每个用户只有一个有效令牌；再次登录替换旧令牌。退出撤销当前令牌。注销删除用户、全部文本和令牌；之后可重新注册同名用户，旧令牌不能恢复有效。

退出、注销和所有文本接口需要 `Authorization: Bearer <token>`。其余接口公开。身份由服务端根据令牌确定，客户端不能指定文本所属用户。缺失、无效或过期令牌返回 401。

服务端使用内存保存账号、令牌和文本，重启后清空。服务端参数 `--token-ttl-seconds` 接受正整数，默认 300。从登录成功起计算固定有效期，不随操作续期；登录响应中的整数 `expires_in` 表示配置的有效秒数。使用适合计算经过时间的时钟，达到期限即失效。

访问或修改受保护数据时检查有效性，身份检查和操作保持一致。已通过检查并完成的数据操作不因发送响应时到期而撤销。注销完成后，旧身份的操作不能重新写入文本。无需刷新令牌接口，过期记录的清理方式自行选择。

## 文本与输入边界

文本名称由 1–64 个 ASCII 字母、数字、下划线或连字符组成，区分大小写。每个用户可以保存多篇文本，同名上传覆盖。只访问自己的文本，列表按名称升序排列；同名文本可分别属于不同用户。获取、删除不存在的文本返回 404。

文本支持 Unicode、换行和空字符串，UTF-8 编码后最多 65,536 字节；echo 使用同样上限。超限返回 413。名称、字段类型或范围不合法返回 400。文本是合法 Unicode 字符串，不接受未配对的代理码位。

HTTP 请求体上限为 524,288 字节，包含 JSON 转义和字段名；超过返回 413。

## 错误响应

错误必须使用对应 HTTP 状态码，不得用 200 包装失败。错误体可省略，也可带 `{"message":"原因"}`；不强制统一结构或具体文案，客户端须按状态码判断，不能依赖 `message` 存在。框架处理的 HTTP 格式错误可使用其原生错误响应。

- **400**：非法 JSON、请求体不是对象、缺少或多出字段、字段类型或范围不合法、文本名称不合法。
- **401**：登录凭据错误，或受保护接口的令牌缺失、无效、已撤销或过期。
- **404**：未知路径，或当前用户要获取、删除的文本不存在。
- **405**：已知路径使用不支持的方法。
- **409**：注册的用户名已存在。
- **413**：文本 UTF-8 字节数或 HTTP 请求体超过上限。

以下为成对的失败示例，响应体仅示意；除指定错误外，其他输入均合法，受保护请求使用有效令牌：

- `POST /echo`，体 `{"text":42}` → 400，`{"message":"text 必须是字符串"}`。
- 再次 `POST /users`，体 `{"username":"alice","password":"password1"}`（alice 尚未注销）→ 409，`{"message":"用户名已存在"}`。
- 不带令牌请求 `GET /texts` → 401，`{"message":"请先登录"}`。
- `GET /texts/missing`（当前用户无此文本）→ 404，`{"message":"文本不存在"}`。

请求读取超时与退出要求见下节；起始路由的 501 仅表示任务尚未实现，不是上述接口的最终响应。

## 运行与并发

同步服务端以同步业务处理作为过渡练习，不要求请求串行执行。异步服务端使用异步请求处理，密码计算等阻塞工作不能占用事件循环。两个服务端都须保护共享状态：注册同名用户只能有一次成功；并发文本操作、登录替换、注销与令牌检查须保持状态一致，不在持锁期间等待网络。

两个服务端分别运行，各自持有独立数据，不需要相互同步。每个程序使用单进程中的存储；Python 保持单个 Uvicorn worker 进程，Rust 的运行时工作线程共享同一份状态。

最终程序要求：

- 客户端从发起 HTTP 操作到读完响应总计最多 12 秒；单次读写超时不等于总期限。
- 服务端从开始接收一个请求到完整读完请求最多 30 秒，分段发送不重置期限；超时关闭连接，可在能够响应时返回 408。空闲 keep-alive 可按框架默认策略关闭。
- Ctrl-C 后停止接收新请求，最多等待在途请求 2 秒，然后终止剩余处理并退出；空闲时也能及时退出。
- 参数错误有明确提示，运行错误不导致其他客户端的状态损坏。

HTTP 框架、库可以调整；以上是最终行为要求，并非要求自行解析 HTTP。
